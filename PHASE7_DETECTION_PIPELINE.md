# Phase 7.2 — Event-Driven ETTH Detection Pipeline Specification

## 1. Overview & Architecture
The **Event-Driven ETTH Detection Pipeline** ([`backend/detection_pipeline.py`](file:///E:/UserBenchmark/encrypted-traffic-threat-hunter/backend/detection_pipeline.py)) orchestrates end-to-end processing for every network flow streamed through the system.

### Processing Lifecycle:
```
FLOW INPUT
    ↓
FEATURE PREPARATION (Flow statistics & TLS handshake parsing)
    ↓
TLS / FINGERPRINT CHECK (JA3, JA4, ALPN presence validation)
    ↓
MODEL ROUTING (A_FLOW, B_JA3, C_JA4, D_JA3_FLOW, E_JA4_FLOW)
    ↓
INFERENCE (InferenceEngine multi-track pipeline)
    ↓
DETECTION EVIDENCE GENERATION (Observable feature statements)
    ↓
CANONICAL EVENT ENVELOPE (ETTHStreamEvent validation)
    ↓
WEBSOCKET BROADCAST (ConnectionManager)
```

---

## 2. Model Track Routing Rules

The detection pipeline supports 5 explicit model tracks matching the research pipeline structure:

| Model Track | Name | Feature Requirements | Behavior When Required Feature Is Missing |
| :--- | :--- | :--- | :--- |
| `A_FLOW` | Flow Stats Only | Flow statistics (duration, packet/byte counts, ratios, asymmetry) | Evaluates flow statistics. |
| `B_JA3` | JA3 Only | `ja3_hash` present | If `ja3_hash` is missing: **SKIPPED** (No fabrication). |
| `C_JA4` | JA4 Only | `ja4` string present | If `ja4` is missing: **SKIPPED** (No fabrication). |
| `D_JA3_FLOW` | JA3 + Flow | `ja3_hash` present AND flow statistics | If `ja3_hash` is missing: **SKIPPED** (No fabrication). |
| `E_JA4_FLOW` | JA4 + Flow | `ja4` string present AND flow statistics | If `ja4` is missing: **SKIPPED** (No fabrication). |

### Strict Non-Fabrication Policy:
When a requested model track requires a fingerprint (e.g. JA3 or JA4) that is absent from the flow record:
- The pipeline **NEVER fabricates** dummy or random hashes.
- The pipeline **NEVER substitutes** another fingerprint.
- The detection status is marked as `SKIPPED` with `prediction: "UNKNOWN"`, `threat_score: 0.0`, and a clear `skip_reason`.

---

## 3. Structured Detection Evidence & Non-Causality

- Every processed event contains an `evidence` list referencing observable feature inclusions.
- **Evidence Wording Policy:** Feature importance is NOT causality. The pipeline describes feature inclusion neutrally:
  - *Correct:* `"JA3 fingerprint 'e7d705a3...' was available and included in model track D_JA3_FLOW feature set."`
  - *Forbidden:* `"JA3 hash caused this flow to be classified as malware."`

---

## 4. Threat Score Semantics & Scientific Caveats

- **Threat Score:** A float value (0.0 to 1.0) generated by `RandomForestClassifier.predict_proba()`.
- **Inference Status:** `REAL_TIME_ENGINEERING_INFERENCE`.
- **Scientific Caveat:** Real-time stream scoring is an engineering demonstration of live pipeline orchestration. It DOES NOT represent generalized real-world malware probability due to pilot source-confounding limitations (DS-008 malicious vs DS-004 benign).
- **Provenance Separation:** Provenance attributes (`dataset_id`, `source_file`, `label_ground_truth`, `caveat`) are stored exclusively in the `provenance` section and are strictly excluded from model feature matrices to prevent data leakage.

---

## 5. Error Isolation & Observability

- **Per-Flow Failure Isolation:** If a malformed flow record triggers an exception during feature extraction or model scoring, the pipeline catches the error and emits a structured fallback event with `status: "ERROR"`. The replay loop continues processing subsequent flows without crashing.
- **Structured Logging:** Emits explicit log entries for `[FLOW_RECEIVED]`, `[INFERENCE_COMPLETED]`, `[INFERENCE_SKIPPED]`, and `[EVENT_EMITTED]` without logging decrypted TLS payloads or raw secrets.
